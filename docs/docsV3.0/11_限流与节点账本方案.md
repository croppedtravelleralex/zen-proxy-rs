# 限流与节点账本方案

## 背景

用户通过 Clash Verge 换 IP 已证实 opencode Zen free model 429 可通过换出口 IP 解除。但 WebShare 反代每个 IP 能吃到的请求数/tokens 比自用 opencode CLI 明显少，说明除了 IP 限流，还可能有：

1. 缺少 official opencode headers 导致进入 `dailyRequestsFallback` 低额度
2. 关键/header 指纹过少，容易被聚类为机器流量
3. 模型级隐藏额度（不同 free model 有不同的 rateLimit）

## 账本数据模型

### LedgerEvent（JSONL 事件）

| 字段 | 类型 | 说明 |
|---|---|---|
| ts | i64 | 时间戳毫秒 |
| rid | String | 请求 ID |
| event_type | String | success / rate_limited / upstream_5xx / network_error |
| node_id | String | WebShare 节点 ID（sha256 前 8 位） |
| node_url_redacted | String | 已脱敏节点 URL，密码部分替换为 `***` |
| model | String | 实际发往上游的模型名 |
| stream | bool | 是否流式 |
| status | u16 | HTTP 状态码 |
| retry_after | Option<i64> | 上游返回的 retry-after 秒数 |
| error_type | Option<String> | 错误类型（upstream_429 / timeout 等） |
| latency_ms | u64 | 延迟 |
| upstream_api_key_hash | String | 所用 API key 的 hash（8 位 hex） |
| user_agent_hash / client_hash / ... | Option<String> | opencode header hash（如可用） |
| prompt/completion/total_tokens | Option<u32> | token 用量 |
| pool_from / pool_to | Option<String> | 池迁移（如 dispatch -> ratelimited） |
| attempt | u32 | 重试次数 |

### 成功请求内存聚合

成功请求**不写入 JSONL**，只在内存中更新以下维度的计数器：

- by_node
- by_model
- by_key
- by_stream

## 写入策略

| 事件类型 | 是否落盘 JSONL | 是否更新内存 |
|---|---|---|
| 2xx 成功 | 否 | 是 |
| 429 | 是 | 是 |
| 5xx 上游错误 | 是 | 是 |
| network error / timeout | 是 | 是 |
| pool transition | 是 | 是 |

JSONL 文件路径：`/tmp/zen-proxy-ledger-events.jsonl`（当前硬编码，后续可配置化）

## 已实现方案

### 本轮完成

1. **src/ledger.rs** -- LedgerCounters + LedgerEvent
   - 内存多维聚合
   - JSONL 事件写入
   - 敏感字段脱敏（redact_node_url、short_hash）
   - 单元测试 5 个

2. **src/proxy.rs** 接入
   - success 分支：记录成功事件（不落盘，仅内存）
   - 429 分支：记录 rate_limited 事件 + JSONL + pool transition
   - 5xx 分支：记录 upstream_5xx 事件 + JSONL
   - network error 分支：记录 network_error 事件 + JSONL

3. **src/main.rs** 初始化
   - LedgerCounters 初始化并注入 AppState
   - 配置 JSONL 写入路径

4. **src/server.rs** admin_nodes_handler
   - 返回 `state.ledger.summary()`
   - 复用 admin auth 鉴权

5. **opencode headers**（src/opencode_headers.rs）
   - 配置开关
   - 注入官方风格 header
   - 仅 hash 暴露给账本

## A/B 实验设计

### 实验 1：current headers vs official headers

1. 同一 WebShare 节点
2. A 组：不设 `OPENCODE_HEADERS_ENABLED`（当前行为）
3. B 组：设 `OPENCODE_HEADERS_ENABLED=true`
4. 同一模型（如 `big-pickle`）
5. 记录：成功请求数、首次 429 时间、retry-after

### 实验 2：不同 free model 对额度影响

1. 同一节点与 headers
2. 分别请求 `big-pickle`、`deepseek-v4-flash-free`、`qwen3.6-plus-free`、`minimax-m2.5-free`
3. 对比 429 触发点和 retry-after

### 实验 3：stream vs non-stream

1. 同一节点、model、headers
2. A：`stream: true`
3. B：`stream: false`
4. 观察 429 触发是否存在差异

## JSONL 使用示例

```bash
# 查看所有 429 事件
grep rate_limited /tmp/zen-proxy-ledger-events.jsonl | head -5

# 按节点统计
jq -r '.node_id' /tmp/zen-proxy-ledger-events.jsonl | sort | uniq -c | sort -rn

# 按 error_type 统计
jq -r '.error_type // "empty"' /tmp/zen-proxy-ledger-events.jsonl | sort | uniq -c | sort -rn

# 查看 pool transition
grep pool_from /tmp/zen-proxy-ledger-events.jsonl | head -10

# 过滤某节点的全部事件
jq 'select(.node_id == "a8f31c2d")' /tmp/zen-proxy-ledger-events.jsonl
```
