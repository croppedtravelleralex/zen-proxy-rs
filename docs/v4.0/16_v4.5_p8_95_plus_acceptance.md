# V4.5 P8 95+ Acceptance Plan

## Purpose

P8 is the release evidence layer for the V4.5+ reliability work. It proves that
NewAPI, ZenProxyRS, the embedded free-model-client kernel, proxy-node selection,
protocol guard, compactor, pool budget, and client compatibility work together
on the same path the user actually runs.

The accepted production chain is:

```text
Windows / WSL / panda client
-> NewAPI
-> ZenProxyRS nginx :4000
-> ZenProxyRS instance :4001/:4002/:4004
-> free-model-client-rs kernel
-> selected proxy node
-> DeepSeek-compatible upstream
```

NewAPI is a gateway and accounting layer only. ZenProxy fixes must be made in
ZenProxyRS/free-model-client-rs, not by changing NewAPI or client prompts.

## 95+ Release Claims

The release is not accepted until fresh evidence supports these claims:

| Area | Claim | Required Evidence |
|---|---|---|
| API | OpenAI and Anthropic compatible endpoints work through NewAPI | `/v1/models`, `/v1/chat/completions`, `/v1/messages`, stream and non-stream cases |
| Protocol Guard | malformed tool histories are repaired or downgraded before upstream | missing `tool_call_id`, missing `input_schema`, orphan tool result, mixed text+tool_result cases |
| Pair-Aware Compactor | large tool histories remain protocol-valid after compaction | audit rows show `protocol_guard.post_valid=true` after compactor paths |
| Streaming | stream decoding errors are classified and rare | no unclassified `error decoding response body`; first byte/content timings recorded |
| Non-stream | large non-stream calls do not stall into opaque 60s 502s | retry chain and failure kind are visible for every 502 |
| Pool | multi-instance scheduling shares node budget and failures | `/admin/pool/state`, `/admin/budget`, `/admin/budget/nodes`, Redis budget snapshots |
| TTFT | long-context latency is measured by bucket | 50K/100K/200K/400K/600K buckets when budget allows |
| Security | evidence contains no secrets or raw prompts | generated records store hashes, counts, timings, and redacted fields only |
| Reconcile | NewAPI and ZenProxy records can be joined | `derived/request-map.jsonl` join rate target >= 95% when request ids are available |

## P0-P8 Scope

P0 Protocol Guard 2.0:

- OpenAI `role=tool` messages without `tool_call_id`.
- assistant `tool_calls[].id` missing.
- Anthropic `tools[].input_schema` missing.
- Anthropic `tool_result.tool_use_id` missing.
- orphan tool result downgrade.
- mixed Anthropic `text + tool_result` ordering.

P1 Pair-Aware Compactor 2.0:

- build tool-pair structure before compaction.
- preserve or summarize tool call/result pairs together.
- keep system/developer/current-task context.
- validate again after compaction.

P2 Streaming Stabilizer:

- SSE half-frame and unusual data-line handling.
- first byte, first content, first tool-call, and stream-complete timings.
- separate upstream bad stream from client disconnect.

P3 Non-stream Large Request Executor:

- non-stream large request timing and retry evidence.
- no unexplainable retry-budget exhaustion.
- conservative retry semantics for tool-call requests.

P4 Multi-Instance Pool:

- global node RPM, concurrency, token budget, and cooldown evidence.
- dead-pool probe state and recovery evidence.
- Redis fail-open behavior evidence.

P5 Ledger and Admin Evidence:

- durable per-request rows.
- `/admin/audit/*` and `/admin/requests/*` coverage.
- NewAPI-to-ZenProxy reconciliation.

P6 TTFT:

- bucketed TTFT experiment records.
- proxy overhead separated from upstream/model delay when data is available.
- cache-affinity and request-size routing evidence.

P7 Security:

- redacted evidence only.
- admin endpoints require a key.
- external errors do not expose paths, proxy URLs, API keys, stack traces, or Redis URLs.

P8 Test and Release:

- all evidence is written under `test-records/runs/<run_id>/`.
- generated run output is not committed.
- Windows, WSL, and panda flows have repeatable instructions.

## Evidence Layout

Every run writes:

```text
test-records/runs/<run_id>/
  manifest.json
  summary.md
  client-smoke.md, when a client smoke was executed
  client-acceptance.md, when Hermes/OpenClaw runner was executed
  raw/
  derived/
    metrics.jsonl
    request-map.jsonl
    tool-repair-summary.json
```

`test-records/runs/` is ignored and must not be committed. Summaries may be
copied into docs only after redaction review.

## NewAPI / ZenProxy Reconciliation

The collector accepts a redacted NewAPI JSONL export and joins it with ZenProxy
audit rows.

Required NewAPI fields:

```json
{"request_id":"...","channel_id":69,"model_name":"deepseek-v4-flash","status":200,"duration_ms":3000,"created_at":1779846868,"is_stream":true,"prompt_tokens":1000,"completion_tokens":50}
```

Join order:

1. `NewAPI.request_id == ZenProxy.external_request_id`
2. nearest timestamp within `--join-time-window-ms`
3. same model and status

Acceptance:

```text
join rate >= 95% when NewAPI request ids are propagated
no raw prompt/completion/tool output stored
unmatched rows are classified as newapi_only or zen_only
```

## Pass / Fail Rules

P0 is pass only if:

- all API smoke cases return expected status.
- tool protocol malformed cases do not return DeepSeek validation errors.
- `tool-repair-summary.json` has no `post_invalid` rows.

P1/P2 are pass only if:

- no unclassified streaming decode failure appears in the run window.
- first byte and first content timings exist for stream cases.

P3 is pass only if:

- every 502 has retry chain and failure kind evidence.
- no request disappears between NewAPI and ZenProxy without classification.

P4 is pass only if:

- all active instances expose budget/pool snapshots.
- a node failure is shared across instances when Redis is available.

P5/P8 are pass only if:

- `summary.md`, `metrics.jsonl`, and `request-map.jsonl` exist.
- records are redacted.
- generated evidence stays out of git.

## Release Gate

Before merging a V4.5/P8 release branch:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --release
python3 -m py_compile scripts/collect_test_record.py scripts/run_chain_smoke.py scripts/run_openclaw_hermes_acceptance.py scripts/run_ttft_experiment.py
scripts/run_v45_p8_acceptance.sh plan
```

The plan command must succeed without API keys or live services. Smoke/client
commands require live NewAPI/ZenProxy and runtime keys.

## Rollback

Testing changes are rollback-safe because they do not change `src`. Runtime
rollback remains:

```text
switch NewAPI channel away from ZenProxy
or switch nginx upstream to the previous binary
or set feature env flags back to observe/off where supported
```

Generated evidence can be deleted without affecting runtime:

```bash
rm -rf test-records/runs/<run_id>
```
