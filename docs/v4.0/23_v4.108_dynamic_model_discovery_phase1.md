# V4.108 Dynamic Model Discovery Phase 1

## Scope

V4.108 Phase 1 adds side-channel discovery for opencode Zen models without
changing production routing.

The hard production contract remains:

```text
GET /v1/models -> deepseek-v4-flash, deepseek-v4-flash-lite
deepseek-v4-flash      -> deepseek-v4-flash-free
deepseek-v4-flash-lite -> big-pickle
```

Discovered models are candidates only. They are not public, not routable, and
not auto-promoted.

## Runtime Switches

```text
DYNAMIC_MODEL_DISCOVERY_ENABLED=false
DYNAMIC_MODEL_DISCOVERY_URL=https://opencode.ai/zen/v1/models
DYNAMIC_MODEL_DISCOVERY_INTERVAL_SECS=1800
```

Defaults are safe:

- discovery is off unless explicitly enabled;
- enabling discovery from a previously disabled process is startup-scoped in
  Phase 1; change the env and restart the instance;
- `worker_running=false` means config may be enabled but no startup discovery
  worker was spawned in this process;
- interval has a lower bound of 60 seconds;
- discovered models are never added to `/v1/models` in Phase 1;
- request model resolution still uses the static V4 registry.

## Candidate Rules

The first safe filter is intentionally narrow:

```text
candidate if id == big-pickle
candidate if id ends_with "-free"
ignored otherwise
```

Every candidate is recorded with:

```text
state=candidate
probe_required=true
auto_promoted=false
public=false
```

This prevents paid or unknown opencode models from being exposed just because
they appear in `/zen/v1/models`.

## Admin Visibility

`GET /admin/models` now includes:

```text
dynamic_discovery.enabled
dynamic_discovery.source_url
dynamic_discovery.last_attempt_unix
dynamic_discovery.last_success_unix
dynamic_discovery.last_error
dynamic_discovery.worker_running
dynamic_discovery.candidate_total
dynamic_discovery.ignored_total
dynamic_discovery.missing_total
dynamic_discovery.models[]
safety.candidates_are_public=false
safety.auto_promote=false
safety.public_models_source=static_registry
```

`GET /admin/models/{model_id}` returns static model details first. If the model
is not public but was discovered, it returns candidate metadata with
`public=false`.

If a previously discovered model is absent from a later upstream list, it is
kept as an admin tombstone with `state=missing`, `probe_required=true`, and
`auto_promoted=false`. Missing models are not public and are not routable.

## Risks Avoided

Phase 1 deliberately avoids:

- exposing every opencode model in `/v1/models`;
- sending user traffic to unprobed free models;
- applying ClaudeCode compatibility policy to unknown model families;
- changing NewAPI, ClaudeCode, cc-switch, or channel 69 configuration;
- consuming proxy resources with aggressive multi-model probes.

## Rollback

Fast rollback is configuration-only:

```text
DYNAMIC_MODEL_DISCOVERY_ENABLED=false
```

If a deployed binary must be reverted, restore the previous `zen-proxy-rs`
binary and rolling-restart the three panda instances. The public model API is
unchanged by this feature, so NewAPI channel 69 does not need to be changed.

## Phase 1 Acceptance

Required before enabling discovery in production:

```text
cargo test v4::model_discovery
/v1/models still returns only the two existing public models
/admin/models shows dynamic_discovery
new candidates have probe_required=true and auto_promoted=false
unknown candidate model remains rejected by data-plane requests
previously discovered models absent from the latest upstream list become missing
discovery failure records last_error but does not affect /health
```

## Phase 2 Preview

Phase 2 may add manual canary promotion, but it must keep the same safety model:

```text
candidate -> canary -> active
active only after smoke/tool/format probes pass
retired models remain visible as tombstones in admin
ClaudeCode compatibility is profile-gated per model family
```
