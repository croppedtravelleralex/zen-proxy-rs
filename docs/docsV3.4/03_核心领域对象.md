# ZenProxyRS_M v3.4 核心领域对象

## 1. Model

模型是资源，不只是字符串。

### 当前基线

当前模型管理非常简陋：
- `config.rs` 中硬编码 4 个映射：`deepseek-v4-flash→big-pickle`, `deepseek-v4-pro→deepseek-v4-flash-free` 等
- `/v1/models` 返回硬编码列表：`deepseek-v4-flash`, `deepseek-v4-pro`
- 无模型注册/查询/更新机制

### v3.4 定义

```rust
struct Model {
    model_id: String,
    provider_id: String,
    display_name: String,
    enabled: bool,
    is_free: bool,
    source: ModelSource,
    capabilities: ModelCapabilities,
    probe_status: ProbeStatus,
    last_seen_at: Option<i64>,
    created_at: i64,
    updated_at: i64,
    metadata: HashMap<String, String>,
}
```

### 枚举

```rust
enum ModelSource {
    Manual,   // 手动添加
    Probe,    // 自动探测
    Upstream, // 上游列表
    Imported, // 导入
}

struct ModelCapabilities {
    chat: bool,
    streaming: bool,
    tool_calling: bool,
    vision: bool,
    embedding: bool,
    json_mode: bool,
    context_window: u32,
    max_output_tokens: u32,
}

enum ProbeStatus {
    Candidate,
    Available,
    Unavailable,
    RateLimited,
    AuthFailed,
    Deprecated,
    Disabled,
}
```

### 用途

1. 手动添加免费模型
2. 自动探测上游新模型
3. 标记模型是否免费
4. 禁用失效模型
5. 将用户请求模型映射到真实 provider 模型（当前 `apply_model_override` 的增强版）

## 2. Provider

Provider 是上游服务。例如：opencode, openrouter, newapi, openai-compatible, ollama。

### 当前基线

- 当前只有 1 个上游：`opencode.ai/zen`
- 硬编码为 `config.upstream_base` 和 `config.upstream_api_key`
- `NodeProvider` trait 只管理代理节点来源，不关心上游服务

### v3.4 定义

```rust
struct Provider {
    provider_id: String,
    kind: ProviderKind,
    base_url: String,
    api_key_ref: String,       // 引用环境变量或配置中的 key
    enabled: bool,
    default_model: Option<String>,
    active_route_id: Option<String>,
    health: ProviderHealth,
    model_discovery_config: Option<ModelDiscoveryConfig>,
    timeout_ms: u64,
    headers_policy: HeadersPolicy,
    metadata: HashMap<String, String>,
}

enum ProviderKind {
    OpenCode,
    OpenAICompatible,
    OpenRouter,
    NewApi,
    Ollama,
    Custom,
}

struct ModelDiscoveryConfig {
    enabled: bool,
    interval_secs: u64,
    candidate_models: Vec<String>,
}
```

### Provider 不绑定死 WebShare

Provider 只表示：
- 我要请求哪个上游服务
- 这个服务支持哪些模型
- 这个服务需要什么认证/headers

## 3. Node

Node 是网络出口或代理节点。

### 当前基线

当前节点管理较为完善：
- `NodeRef` 结构体：`{ id: String (SHA256[:8]), url: String }`
- 五池状态机管理节点生命周期（Dispatch/Active/RateLimited/Dead/ProbePeriod）
- `DispatchPool` 加权评分选择节点
- 但节点信息较简单，缺少 region/tags/limits 等元数据

### v3.4 定义

```rust
struct Node {
    node_id: String,
    name: String,
    kind: NodeKind,
    endpoint: String,
    enabled: bool,
    region: Option<String>,
    tags: Vec<String>,
    health: NodeHealth,
    latency_ms: Option<f64>,
    egress_ip: Option<String>,
    last_check_at: Option<i64>,
    limits: NodeLimits,
    metadata: HashMap<String, String>,
}

enum NodeKind {
    Direct,
    HttpProxy,
    Socks5,
    WebShare,
    Custom,
}

struct NodeHealth {
    status: HealthStatus,
    success_count: u64,
    failure_count: u64,
    consecutive_failures: u32,
    last_failure_kind: Option<FailureKind>,
}

struct NodeLimits {
    max_concurrent: u32,
    max_requests_per_min: Option<u32>,
    max_bytes_per_min: Option<u64>,
}

enum HealthStatus {
    Unknown,
    Healthy,
    Degraded,
    Unhealthy,
    Dead,
}
```

### Node 不知道模型

Node 只管：
- 我能不能作为出口
- 我是否可用
- 我延迟多少
- 我失败率多少

## 4. Route

Route 是 Provider 到 Node 的绑定关系。

```
provider -> route -> node
```

### 当前基线

❌ Route 概念完全不存在。当前架构是：
- `PoolManagerImpl` 从 dispatch 池取一个节点
- 直接通过该节点发送请求到固定 `upstream_base`
- Provider 和 Node 之间无中间层

### v3.4 定义

```rust
struct Route {
    route_id: String,
    provider_id: String,
    node_id: String,
    enabled: bool,
    priority: u32,
    weight: u32,              // 用于加权选择
    policy_id: Option<String>,
    health: RouteHealth,
    last_used_at: Option<i64>,
    failure_count: u64,
    success_count: u64,
    metadata: HashMap<String, String>,
}
```

### 示例

```
opencode -> webshare-us-1
opencode -> webshare-sg-2
openrouter -> direct
newapi -> local-lan
```

这样以后 opencode 换成别的 Provider，不影响 Node。WebShare 换成别的代理，也不影响 Provider。

## 5. RequestRecord

请求调用记录是 v3.4 的关键对象。

### 当前基线

当前有**两套**记录系统：

**LedgerCounters（ledger.rs）：**
- 18 字段 LedgerEvent：ts, rid, event_type, node_id, node_url_redacted, model, stream, status, retry_after, error_type, latency_ms, token 字段, pool_from/pool_to, attempt
- 写入：非 2xx + 池转换时写 JSONL
- 维度：按 node/model/key/stream 聚合

**DataCollector（collector/*）：**
- 22 字段 RequestTelemetry：rid, ts, model, client_id, path, method, is_streaming, node_url(脱敏), pool, exit_ip, status, rate_limited, retry_count, latency_total_ms, upstream_ms, ttft_ms, token 字段, bytes_sent, bytes_received
- 写入：RingBuffer（10k 条）+ 可选的 WAL
- 已知问题：Telemetry 仅 47.6% 字段正确填充，失败请求不触发 record_request

### v3.4 统一定义

```rust
struct RequestRecord {
    // 身份
    request_id: String,
    timestamp: i64,

    // 客户端
    client_id: Option<String>,

    // 链路追溯
    provider_id: Option<String>,
    provider_kind: Option<String>,
    model_id: String,
    node_id: Option<String>,     // SHA256[:8] 脱敏
    route_id: Option<String>,

    // 请求信息
    method: String,
    path: String,

    // 结果
    status: RequestStatus,       // success | rate_limited | upstream_error | network_error | timeout
    http_status: u16,
    error_code: Option<String>,
    error_message: Option<String>,

    // 性能
    latency_ms: u64,             // 总延迟（含重试）
    upstream_ms: Option<u64>,    // 上游响应时间（不含重试）
    ttft_ms: Option<u64>,       // 首 token 时间（流式）

    // 流量
    bytes_sent: u64,
    bytes_received: u64,

    // Token
    prompt_tokens: Option<u32>,
    completion_tokens: Option<u32>,
    total_tokens: Option<u32>,
    tokens_per_response_kb: Option<f64>,
    tokens_per_total_kb: Option<f64>,

    // 重试
    retry_count: u32,

    // 流式
    is_streaming: bool,

    // 元数据
    created_at: i64,
}
```

### 直接支撑

- `/admin/requests` 查询
- 成本估算
- token/KB 指标
- 节点质量分析
- 模型质量分析
- Provider 质量分析

## 6. EventRecord

事件和请求日志分开。

### 当前基线

当前事件分散在：
- `LedgerEvent`：错误/转换事件（写 JSONL）
- `PoolEvent` / `ProbeEvent` / `SystemEvent`：collector 中的事件类型
- 但无统一查询接口

### v3.4 定义

```rust
struct EventRecord {
    event_id: String,
    timestamp: i64,
    level: EventLevel,
    source: EventSource,
    event_type: EventType,
    entity_id: Option<String>,
    message: String,
    details: Option<serde_json::Value>,
    created_at: i64,
}

enum EventLevel { Info, Warning, Error, Critical }
enum EventSource { System, Provider, Node, Route, Model, Auth, Config }

enum EventType {
    // 节点
    NodeHealthChanged,
    NodeDisabled,
    NodeEnabled,
    // Provider
    ProviderHealthChanged,
    ProviderRouteSwitched,
    // 模型
    ModelProbeStarted,
    ModelProbeSucceeded,
    ModelProbeFailed,
    // 熔断
    FuseOpened,
    FuseClosed,
    FuseReset,
    // 请求
    RequestRetry,
    // 配置
    ConfigReloaded,
    // 认证
    AuthFailed,
    // 系统
    SystemStarted,
    SystemShutdown,
}
```

## 7. FuseState

熔断不应该只有全局开关。应该支持多 scope。

### 当前基线

- 单个 `AtomicBool`（`PoolManagerImpl`）
- `fuse_all()`：把所有节点从 dispatch 移到 dead
- `unfuse_all()`：把所有 dead 节点移回 dispatch
- GET `/admin/fuse` 返回 `{"fuse": true/false, "pools": {...}}`

### v3.4 多 scope 定义

```rust
enum FuseScope {
    Global,
    Provider,
    Node,
    Route,
    Model,
}

struct FuseState {
    scope: FuseScope,
    entity_id: String,        // "_" for global
    state: FuseStateValue,
    failure_count: u64,
    success_count: u64,
    opened_at: Option<i64>,
    next_retry_at: Option<i64>,
    policy_id: Option<String>,
    reason: Option<String>,
    ttl_seconds: Option<u64>,
}

enum FuseStateValue {
    Closed,
    Open,
    HalfOpen,
}
```

### 用途

- global `_`：全局禁手
- provider `opencode`：仅禁用该 provider
- node `abc123`：仅禁用该节点
- route `route-1`：仅禁用该 route
- model `big-pickle`：仅禁用该模型
