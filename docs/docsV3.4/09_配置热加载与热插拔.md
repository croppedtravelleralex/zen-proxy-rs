# ZenProxyRS_M v3.4 配置、热加载与热插拔

## 1. P0 配置策略

建议先用 JSON/TOML，不上数据库。

```
config/
  providers.json    Provider 配置
  models.json       模型配置
  nodes.json        节点配置（当前已有）
  routes.json       Route 配置
  policies.json     策略配置

data/
  requests.wal.jsonl    请求日志 WAL
  events.wal.jsonl      事件日志 WAL
  snapshots.json        定期快照
```

### 当前基线

所有配置从环境变量读取（~40 个），通过 `Config::from_env()` 加载。

```rust
// config.rs 中的关键配置字段
PORT, BIND_ADDRESS, UPSTREAM_BASE, UPSTREAM_API_KEY
ADMIN_API_KEY, PROXY_API_KEY
POOL_MAX_RETRIES, POOL_MAX_CONCURRENT
MODEL_OVERRIDE, MODEL_MAPPING
OPENCODE_HEADERS_ENABLED, OPENCODE_VERSION, ...
LEDGER_EVENTS_PATH, NODES_FILE
UPSTREAM_TIMEOUT_SECS, ALLOW_DIRECT_FALLBACK
GLOBAL_BACKOFF_COOLDOWN_SECS, POOL_STARVATION_RETRY_AFTER_SECS
```

### v3.4 建议

环境变量 → `Config` 作为启动配置。运行时用 Admin API（`POST /admin/providers`、`POST /admin/nodes` 等）管理 provider/model/node/route 的增删改。JSON 配置文件仅做**启动加载**，不做运行时同步。

**重要：** Admin API 是运行时状态管理的唯一权威路径。详见 [Admin API 总体契约](./07_Admin_API总体契约.md) 第 0 章。

## 2. 热加载

### 当前：SIGHUP 已实现

```rust
// main.rs
let reload_config = config.clone();
tokio::spawn(async move {
    let mut sigterm = signal(SignalKind::hangup())?;
    loop {
        sigterm.recv().await;
        reload_config.reload().await;
    }
});
```

`config.reload()` 会重新读取环境变量并更新配置。

### v3.4 新增

```
POST /admin/config:reload
```

触发相同逻辑的 API 端点。

### SIGHUP 范围定义

SIGHUP（以及 `POST /admin/config:reload`）只重新加载静态配置，不重置运行时状态：

| 重新加载 | 不操作 |
|---|---|
| providers.json → Provider 列表 | Pool 中节点的分配状态 |
| nodes.json → Node 列表 | 健康统计、延迟数据 |
| routes.json → Route 列表 | Ledger 计数、RingBuffer |
| models.json → Model 列表 | WAL、事件缓冲、JSON 快照 |
| policies.json → 熔断开关默认值 | 进行中的请求 |

**实现注意：** SIGHUP handler 只更新 `AppState` 中的配置字段。不调用 Pool 子池的方法。

### P1：文件 watcher

通过 `notify` crate 监听配置文件变化自动 reload。

## 3. 热加载边界

| 可热加载 | 不建议热加载 |
|---|---|
| models | bind address |
| providers | port |
| nodes | storage backend type |
| routes | runtime worker config |
| policies | TLS 证书 |
|  | 日志级别 |
|  | admin tokens（支持 API 动态调整，无需 reload） |

## 4. P1：RegistrySnapshot

内部维护一个不可变快照：

```rust
struct RegistrySnapshot {
    models: HashMap<String, Model>,
    providers: HashMap<String, Provider>,
    nodes: HashMap<String, Node>,
    routes: HashMap<String, Route>,
    policies: HashMap<String, Policy>,
    version: u64,
}
```

- 请求开始时读取当前快照
- reload 时构造新快照，原子替换（`Arc<RegistrySnapshot>`）
- 不影响正在处理的请求
- 避免锁竞争

## 5. P2：Adapter 插件化

Rust 真动态插件复杂，不建议 P0 做 .so/.dll。

| 阶段 | 方式 | 说明 |
|---|---|---|
| P0 | 编译期注册 | trait + 枚举匹配 |
| P1 | 配置期启用/禁用 | 配置文件开关 adapter |
| P2 | WASM adapter | 沙箱化动态加载 |
| P2 | External sidecar | 通过 HTTP/gRPC 通信 |

### 启动环境变量 vs 运行时 API 边界

```
启动专用（进程重启生效）:
  PORT, BIND_ADDRESS, UPSTREAM_BASE, UPSTREAM_API_KEY
  NODES_FILE, LEDGER_EVENTS_PATH, TELEMETRY_WAL_PATH

运行时 API（Admin 端点，立即生效）:
  POST /admin/providers, POST /admin/nodes, POST /admin/routes
  POST /admin/fuse/{scope}/{id}:open/close
  POST /admin/nodes/{id}/recover, POST /admin/nodes/{id}/probe
  POST /admin/config/reload

混合（环境变量为启动默认，API 可运行时覆盖）:
  OPENCODE_HEADERS_ENABLED — 默认 true，API 可关闭
  ALLOW_DIRECT_FALLBACK — 默认 true，API 可关闭
  POOL_MAX_RETRIES — 默认 3，API 可调整
```

以上修改确保：**改环境变量和改 API 不冲突**。启动时加载 env，运行时改内存，SIGHUP 重置为 env 值。
