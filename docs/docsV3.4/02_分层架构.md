# ZenProxyRS_M v3.4 分层架构

## 总览

建议分为 8 层，从下到上：

```
L7  Admin/API Layer      管理接口层
L6  Control Plane        控制面（注册中心/管理器）
L5  Observability Plane  观测面（账本/事件/指标）
L4  Routing/Policy Layer  路由/策略层
L3  Provider Adapter Layer  上游适配层
L2  Transport/Proxy Layer   传输/代理层
L1  Storage/Config Layer    存储/配置层
L0  Runtime                 运行时
```

---

## L7 - Admin/API Layer

**职责：**
- 对外提供管理接口
- 处理认证
- 处理请求参数
- 返回统一响应格式
- 不直接写底层状态

**包含：**
- `/admin/models` CRUD + probe
- `/admin/providers` CRUD + route switch + probe
- `/admin/nodes` CRUD + operate
- `/admin/routes` CRUD + operate
- `/admin/requests` 查询 + 详情 + 聚合
- `/admin/events` 查询 + 流
- `/admin/fuse` 多 scope 管理
- `/admin/health` 详细状态 + live/ready
- `/admin/metrics/summary`
- `/admin/config:reload`

**当前基线：**
- `server.rs` 中有 4 个 GET 处理函数，认证用 `check_admin_auth()` 内联函数
- 响应格式：当前返回 `serde_json::json!({})` 无统一包装
- v3.4 需增加统一响应包装和 AuthGate 抽象

---

## L6 - Control Plane

**职责：**
- 管理模型、Provider、节点、Route、熔断、探测任务

**包含：**

| 组件 | 职责 | 当前基线 |
|---|---|---|
| ModelRegistry | 模型注册/查询/更新/删除 | ❌ 不存在 |
| ProviderRegistry | 上游 provider 管理 | ❌ 不存在 |
| NodeManager | 代理节点管理 | 部分：PoolManager 管理节点池 |
| RouteManager | provider→node 链路管理 | ❌ 不存在 |
| FuseManager | 多 scope 熔断管理 | 部分：单一 AtomicBool |
| ProbeScheduler | 探测任务管理 | 部分：内联在 PoolManagerImpl 中 |
| ConfigManager | 配置管理/热加载 | 部分：SIGHUP 已实现 |

---

## L5 - Observability Plane

**职责：**
- 记录请求
- 记录事件
- 导出指标
- 提供审计

**包含：**

| 组件 | 职责 | 当前基线 |
|---|---|---|
| RequestLedger | 请求调用记录查询 | 部分：LedgerCounters + DataCollector 两份数据 |
| EventStore | 系统事件查询 | 部分：LedgerEvent JSONL 写入中 |
| MetricsCollector | 指标收集 | 部分：PrometheusBackend 已实现 |
| AuditLogger | 管理员操作审计 | ❌ 不存在 |

**关键问题：** `LedgerCounters` 和 `DataCollector` 是两套独立的数据采集系统，数据格式不兼容：
- `LedgerCounters`（ledger.rs）：18 字段 LedgerEvent，按 node/model/key/stream 维度聚合
- `DataCollector`（collector/*）：22 字段 RequestTelemetry，RingBuffer + RollingAggregator + WAL

v3.4 需要统一成 `RequestRecord` 数据模型。

---

## L4 - Routing/Policy Layer

**职责：**
- 决定请求走哪个 provider、哪个 route、哪个 node

**包含：**

| 组件 | 职责 | 当前基线 |
|---|---|---|
| ModelResolver | 用户模型名 → provider/model | 内联在 `utils.rs:apply_model_override()` |
| RouteSelector | 从候选 routes 选一个 | ❌ 不存在 |
| RetryPolicy | 重试策略 | 内联在 `proxy.rs:proxy_with_retry()` |
| HealthPolicy | 健康策略 | `DispatchPool` 评分中隐含 |
| CostPolicy | 成本策略 | ❌ 不存在 |
| RateLimitPolicy | 限流策略 | ❌ 不存在 |
| FallbackPolicy | 降级策略 | `ALLOW_DIRECT_FALLBACK` 已实现 |

---

## L3 - Provider Adapter Layer

**职责：**
- 适配不同上游服务

**当前基线：** 只有 `trait NodeProvider`（3 方法：`all_urls` / `id_for_url` / `name`），只有 `WebShareProvider` 实现。没有 `ProviderAdapter` trait。

**v3.4 新增：** `trait ProviderAdapter`

| 方法 | 职责 |
|---|---|
| `list_models()` | 列出上游支持模型 |
| `probe_model()` | 探测模型可用性 |
| `build_request()` | 构造上游请求 |
| `parse_response()` | 解析响应 usage |
| `parse_error()` | 解析错误 |
| `parse_stream()` | 解析 streaming SSE |

**目标适配器：**
- OpenCodeAdapter（当前唯一的真实上游）
- OpenAICompatibleAdapter（通用 OpenAI 兼容接口）
- OpenRouterAdapter（OpenRouter 上游）
- NewApiAdapter（New-API 上游）
- OllamaAdapter（本地 Ollama）
- CustomProviderAdapter（自定义，通过配置描述）

---

## L2 - Transport / Proxy Layer

**职责：**
- 负责怎么把请求送出去

**当前基线：** 只有 SOCKS5 传输，`reqwest::Client` 在 `DispatchPool::add()` 中内联创建。没有 `TransportAdapter` trait。

**v3.4 新增：** `trait TransportAdapter`

| 方法 | 职责 |
|---|---|
| `send()` | 发送 HTTP 请求 |
| `probe_node()` | 探测节点可用性 |
| `resolve_egress_ip()` | 解析出口 IP |
| `measure_latency()` | 测量延迟 |

**目标传输：**
- DirectTransport：直连，无代理
- HttpProxyTransport：HTTP 代理
- Socks5Transport：SOCKS5 代理（当前方式抽象化）
- WebShareTransport：WebShare 特定封装
- CustomTransport：自定义

---

## L1 - Storage / Config Layer

**职责：**
- 配置、状态、日志、持久化

**当前基线：**
- 配置：~40 环境变量 → `Config` 结构体
- 日志：`LedgerEvent` → JSONL 文件
- 内存：`RingBuffer`（10k 条）/ `RollingAggregator`（12 窗口 × 300s）
- 持久化：`WAL` 代码完整但默认未激活（`wal: None`）

**v3.4 P0 推荐：**

```
config/
  providers.json    Provider 配置
  models.json       模型配置
  nodes.json        节点配置（当前已有）
  routes.json       Route 配置
  policies.json     策略配置

data/
  requests.wal.jsonl    请求日志 WAL
  events.wal.jsonl      事件日志 WAL
  snapshots.json        定期快照
```

P1/P2 再考虑：SQLite / 索引查询 / 压缩归档 / Dashboard 后端。

---

## L0 - Runtime

**当前已用（不需大动）：**

| 依赖 | 版本 | 用途 |
|---|---|---|
| Tokio | 1 | 异步运行时 |
| Axum | 0.8 | HTTP 框架 |
| Reqwest | 0.12 | HTTP 客户端 + SOCKS |
| Tower | 0.5 | 中间件 |
| Tracing | 0.1 | 日志 |
| Serde | 1 | 序列化 |
| futures | 0.3 | 流处理 |

**新增建议（P1/P2）：**
- `opentelemetry`：OpenTelemetry 导出（可选）
- `rusqlite`：SQLite 支持（可选）
- `notify`：文件变化监听（可选，用于自动热加载）
