# ZenProxyRS_M v3.4 请求全链路流程

## 目标链路

```
Client → /v1/chat/completions → 生成 RequestContext → 解析请求体
  → ModelResolver（用户模型名→provider/model，检查 enabled/streaming/tool）
  → ProviderRegistry（找 provider，找 adapter）
  → RouteManager（找 provider 可用 routes）
  → RouteSelector（根据健康/权重/优先级/熔断选择 route）
  → NodeManager（找 node，判断 enabled/healthy）
  → TransportAdapter（direct/http/socks5/webshare）
  → ProviderAdapter.build_request（headers, body, model mapping）
  → 发送上游请求
  → ProviderAdapter.parse_response（body, usage, streaming）
  → RequestLedger.record / MetricsCollector / EventStore
  → 返回 Client
```

## 当前实际链路（v3.0）

```
Client → proxy_handler
  → 提取 client_id（Authorization Bearer，可选）
  → apply_model_override（模型名重写 + -nothinking）
  → 解析体 → model + stream
  → proxy_with_retry（循环 0..max_retries）
    ├─ PoolManagerImpl::dispatch()
    │   ├─ fuse? → NoResource
    │   ├─ DispatchPool::acquire() → 加权评分选节点
    │   └─ 池空且allow_direct_fallback? → 直连 client
    ├─ 构建请求：method + URL + Content-Type + x-api-key + opencode headers + body
    ├─ 发送
    │   ├─ <400 → report(Success) → 释放回池
    │   ├─ 429 → report(RateLimited) → 限流池 + LedgerEvent
    │   ├─ 500+ → report(Error) → 死亡池 + LedgerEvent
    │   ├─ 连接错 → report(Error) → 死亡池 + LedgerEvent
    │   └─ 流式 → stream_to_axum → SseBuffer → patch_sse_line
    ├─ 重试：429/5xx/unreachable + attempt<max_retries
    │   └─ smart_backoff（退避+抖动）
    └─ 记录：DataCollector::record_request + LedgerCounters::record
  → 返回 Client
```

## v3.0 链路已知缺陷

通过反编译 opencode 源码 + WSL 实机抓包验证，当前 v3.0 链路存在 **6 个关键缺陷**：

| # | 缺陷 | 位置 | 代码证据 | 后果 |
|---|---|---|---|---|
| 1 | **100 IP 轮询触发 WAF** | 架构设计 | 100 个 WebShare IP 以相同 payload 模式同时请求 opencode | Cloudflare WAF 判定爬虫，提前拦截 |
| 2 | **缺少 opencode 头 → 指纹不一致** | `config.rs:91` | `opencode_headers_enabled` 默认 `false` | WAF 指纹不匹配，丢 session 粘滞 |
| 3 | **Probe 不带 API key** | `probe_period.rs` | `_api_key` 下划线前缀，故意不用 | Probe 401 → 节点永不恢复 |
| 4 | **重试选新节点** | `proxy.rs:175` | 每次 retry 调 dispatch() 选新节点 | 加速池耗尽 |
| 5 | **PROXY_API_KEY 不校验** | `proxy.rs:47` | 声明了 `proxy_api_key` 但 proxy_handler 不校验 | 无认证，任何人都能用 |
| 6 | **原始 headers 不转发** | `proxy.rs:197` | 请求从零构建，只保留 Content-Type + x-api-key | 指纹丢失 |

**详细分析及修复方案见：[Phase 0.5：请求指纹对齐与 WAF 规避](../13_最优实施路线.md#phase-05请求指纹对齐与-waf-规避p0--核心代理路径修复)。**

## 主要差异

| 环节 | v3.0 现状 | v3.4 目标 | 变化 |
|---|---|---|---|
| 模型名解析 | `apply_model_override()` + 静态映射 | `ModelResolver` → `ModelRegistry` | 适配 |
| Provider 选择 | 固定 `upstream_base` | `ProviderRegistry` → `RouteManager` | 新增 |
| Route 选择 | 不存在 | `RouteSelector` | 新增 |
| 节点选择 | `DispatchPool::acquire()` | `RouteSelector` → `NodeManager` → `TransportAdapter` | 适配 |
| 请求构造 | 直接构造 reqwest::Request | `ProviderAdapter::build_request` | 抽象 |
| 响应解析 | 直接处理 | `ProviderAdapter::parse_response` | 抽象 |
| SSE 处理 | `SseBuffer` + `patch_sse_line` | `ProviderAdapter::parse_stream` | 适配 |
| 账本记录 | 两套系统并行 | 统一 `RequestLedger::record` | 统一 |
| 熔断 | 单一 AtomicBool | `FuseManager` 多 scope | 增强 |

## 6. 请求指纹与 WAF 规避

### 核心问题

代理多 IP 轮询模式下，请求指纹一致性对避免 WAF 触发至关重要。

### 根因分析（来自 opencode 源码深度逆向）

通过反编译 `sst/opencode` commit `b2baddcd`（当前生产环境基线版本），确认限流机制：

**源码文件：** `packages/console/app/src/routes/zen/util/ipRateLimiter.ts`

```typescript
export function createRateLimiter(modelId, rateLimit, rawIp, request) {
  const limits = Subscription.getFreeLimits()
  const dailyLimit = rateLimit ?? limits.dailyRequests
  // 注意：当前生产版本（b2baddcd）无 checkHeaders 逻辑
  // anomalyco/opencode dev 分支已增加 checkHeaders（后续更新）
  
  // 终身计数器 + 日计数器
  const lifetimeInterval = ""    // 总请求量
  const dailyInterval = buildYYYYMMDD(now)  // 日分片

  _isNew = isDefaultModel && lifetimeCount < dailyLimit * 7
  
  if ((_isNew && dailyCount >= dailyLimit * 2)   // 新 IP: 2x 额度
    || (!_isNew && dailyCount >= dailyLimit))     // 老 IP: 1x 额度
    throw new FreeUsageLimitError("...", getRetryAfterDay(now))
}

function getRetryAfterDay(now) {
  return Math.ceil((86_400_000 - (now % 86_400_000)) / 1000)
  // 返回到午夜 UTC 的秒数
}
```

关键发现：
1. **限流按 IP，按天重置**（UTC 午夜 = 北京早 8 点），额度用完到午夜解封
2. **新 IP 有新手奖励**：前 `dailyLimit × 7` 次终身请求内，日额度翻倍
3. **当前生产版本 opencode headers 不影响额度**（anomalyco 分支后续版本已增加 checkHeaders）
4. **免费模型永远走 IP 限流** —— `allowAnonymous = true` 强制走 `ipRateLimiter`，给 API key 也没用
5. **Key 限流器默认 500 次/分钟/模型**（`keyRateLimiter.ts`），只在认证模型且 `allowAnonymous = false` 时触发
6. **Trial 限流器**按 IP 累计 token 总量，超过 `promoTokens` 阈值后不再走 trial provider
7. **`dailyRequests` 和 `promoTokens` 具体数值是 SST Secret**，不在开源代码中

### 关键要求

1. **同一 route 的请求指纹必须稳定** — Headers/payload 结构不可频繁变化
2. **Probe 请求的指纹必须与真实请求对齐** — 当前 probe 不带 API key 是致命 bug
3. **建议发送 opencode 特定头** — 不影响额度，但影响指纹一致性 + 粘滞路由 + 未来兼容
4. **出口 IP 切换频率必须控制** — 100 IP 同时轮换被 WAF 判定爬虫

### v3.4 全链路中的指纹点

| 环节 | 影响 WAF 的属性 | v3.4 控制方式 |
|---|---|---|
| TransportAdapter | 出口 IP、连接方式 | RouteSelector 决定使用哪个 node |
| ProviderAdapter.build_request | Headers、UA、payload 结构 | ProviderAdapter 统一构造 |
| RouteSelector | 同一 client 是否走同一 route | StickyByClient / StickyByModel |
| NodeManager | 节点复用频率 | Sticky TTL + 渐进切换 |
| ProbeScheduler | Probe 请求的指纹 | 复用 ProviderAdapter 逻辑 |

### 修复方向（详见 Phase 0.5）

| 措施 | 优先级 | 效果 |
|---|---|---|
| 启用 opencode headers（改默认值） | P0 | 指纹对齐 |
| 粘滞路由（同 client 同 node） | P1 | 避免 100 IP 同时轮询 |
| 每 route 并发上限 | P1 | 降低 WAF 检测概率 |
| Probe 带 API key | P0 | 探活结果可信 |
| 重试优先同一节点 | P0 | 不加速池耗尽 |
