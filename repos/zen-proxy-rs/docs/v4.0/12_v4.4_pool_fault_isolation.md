# V4.4 Pool Fault Isolation

## Goal

V4.4 fixes the 2026-05-26 production incident where healthy Webshare nodes were
misclassified as Dead after upstream failures. The change is intentionally
source-side only: NewAPI and Claude Code behavior are not part of this fix.

Target chain:

```text
Client / Claude Code / CherryStudio
-> NewAPI :8081
-> ZenProxyRS :4000
-> embedded free-model-client-rs kernel
-> selected Webshare node
-> opencode.ai/zen
```

## Incident Evidence

From 2026-05-26 09:00 CST to the investigation window:

- ZenProxy audit requests: 336.
- Success: 309.
- Failures: 27.
- Failure shape: `retry_budget_exhausted` around 120 seconds.
- Runtime state before fix: `dispatch=40`, `dead=50`, `active=9`.
- External lightweight probes of all 50 Dead nodes succeeded: 50/50 OK.

Conclusion: the dead pool was not real proxy death. ZenProxy was punishing
proxy nodes for upstream/model failure and was also leaving stale active counts.

## Landed Changes

Fault classification now separates hard proxy failure from soft upstream
failure.

Hard failures still move a node to Dead:

- SOCKS handshake failure.
- connection refused.
- DNS failure.

Soft failures do not move a node to Dead:

- upstream 5xx.
- timeout classified above the proxy transport boundary.
- empty assistant output.
- retry-budget exhaustion.
- other app-level upstream errors.

Soft failures still matter: they reduce node score and adaptive concurrency, so
weak or unlucky nodes cool down without being buried.

Dispatch selection now samples shards before using a global-best fallback. This
prevents one high-score node from monopolizing traffic while preserving a
fallback path when the sampled candidates cannot admit a request.

Active-pool release is saturating. A double-release or missing active entry can
no longer underflow or leave inflated active totals in normal accounting.

## Acceptance

V4.4 is accepted when:

- unit tests cover soft-failure no-bury behavior;
- hard proxy errors still move nodes to Dead;
- dispatch no longer locks to one global best node;
- `cargo test --tests` passes;
- `cargo build --release` passes;
- NewAPI smoke tests pass for both public models in stream and non-stream mode;
- runtime pool counters settle back to `active=0` and do not create false Dead
  growth after smoke traffic.
